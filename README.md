# mkt-ui

The market data platform's UI at **https://mkt.billandjessie.com**: Treasury yield curves, series and the security master, behind Authentik login. Its server calls mkt-api (`mkt-api:8000`, internal) for the signed-in user; mkt-api answers from secmaster-svc and quote-svc. The plan and status live in mkt-data's [docs/phase-2.md](https://github.com/bcalaway/mkt-data/blob/main/docs/phase-2.md) (Part B, step B9).

It runs on the home platform's AWS hub (`bcalaway/nyc_pa_aws_gitops`) as a registry app (`apps/registry.yml`: Authentik client, no database, no Airflow, no previews). Started from `templates/react` there; [docs/app-platform.md](https://github.com/bcalaway/nyc_pa_aws_gitops/blob/main/docs/app-platform.md) is the platform contract.

## How it runs

- **Container:** one Express process on 8000 serving the built React frontend (TypeScript, Vite) and the server routes. Traefik routes `mkt.billandjessie.com` to it. No database.
- **Hostname:** the app is named `mkt-ui` everywhere on the platform (ECR repo, roles, Authentik application slug and issuer `/application/o/mkt-ui/`), but browsers use `mkt.billandjessie.com` (Bill, 2026-10-04). `PUBLIC_HOST` in `deploy/docker-compose.yml` sets the OIDC redirect; the Traefik rule beside it and the platform's `blueprints/mkt-ui-oidc.yaml` use the same host.
- **Auth:** Authentik OIDC (Pattern A). The client id and secret are generated by the platform (`/home-platform/authentik/mkt-ui-client-*`) and arrive as `AUTHENTIK_CLIENT_ID` / `AUTHENTIK_CLIENT_SECRET`. With them set, every route but `/health`, `/login` and `/auth/callback` needs a session (`/api/*` gets 401, pages redirect to `/login`).
- **Session cookie:** signed with `SESSION_SECRET` if `/home-platform/mkt-ui/session-secret` exists, otherwise with a key derived from the client secret (`server/config.js`). Never the dev default once login is on.
- **CI/CD:** `ci.yml` runs the platform's `app-ci.yml` on every PR (`ci / Build, test, lint` is required on `main`). `cd.yml` builds, pushes and deploys on merge. Docs-only merges don't deploy.

## Screens

Each screen is a self-contained module under `src/screens/` that registers its route in `src/screens/index.ts`; the address bar holds each view's state, so every view can be bookmarked.

- **Curve** (`/`): the Treasury curve on a date (default the latest) against the same curve 1W, 1M, 3M or 1Y earlier (all four by default), with a table of the values and exact changes in basis points.
- **Over time** (`/series`): up to four tenors (2Y, 10Y and 30Y by default) and the 2s10s or 3m10y spread, opening on the last year and zooming from all of history (since 1962) to days, as lines or OHLC bars; the source on hover. Adding or removing a line, or changing the style, source or loading, keeps the window on screen; so does adding or removing a curve on the Curve page. Bars follow the zoom: monthly beyond about 15 years on screen, weekly beyond about 3, daily within. **Loading** chooses how: *Cached blocks* (mkt-api's `/api/bars`, one fixed block at a time: a year of days, a decade of weeks or months; each block is fetched once per page and the blocks either side of the window ahead of need, `src/charts/blocks.ts`; finished blocks are also kept by the browser for a day, the server passing mkt-api's `Cache-Control` through) or *Load every day once* (`/api/series/daily`, bars made in the browser). Both stay for a while to gain experience with each (Bill, 2026-10-06); under each chart its requests (and how many were fetched ahead), bytes, loads answered from the cache, and the last waited-for request's time split into mkt-api's, quote-svc's and the network's (`Server-Timing`, passed through by the server with its own `proxy` time). The direction is the first: mkt-data's `docs/phase-2.md`, "Charts that grow".
- **Instruments** (`/instruments`, `/instruments/UST-10Y-CMT`): search by short name, alias or any source's key; an instrument's identifiers, notes and latest value.

Charts: TradingView Lightweight Charts for time series, ECharts for the curve, each behind the UI's own component (`src/charts/`) so either can be swapped. Every chart has the same toolbar (`src/charts/ChartToolbar.tsx`): jumps to a span where a chart offers them (1M to 10Y over time), then **All**; the wheel, a pinch or a drag zooms in between (Bill, 2026-10-06). Colors are the data-viz reference palette's first four categorical slots, light and dark (`src/charts/theme.ts`); every chart has a legend or table beside it.

## The API and its types

The browser calls only this server: `/api/*` is passed to mkt-api (`MKT_API_URL`, default `http://mkt-api:8000`) for the signed-in user. Values arrive as decimal strings (`"4.10"`) and are shown as given; the one difference computed here (a curve's change in basis points) uses exact decimal arithmetic (`src/decimal.ts`), never floats.

The client is typed from mkt-api's OpenAPI schema: `api/openapi.json` is a copy of mkt-api's, `npm run gen:api` (run by `build` and `lint`) writes `src/api/schema.d.ts`, and `tsc --noEmit` in `lint` fails on anything that no longer fits. A test fails when mkt-api's `main` has a different schema, so an API change there is picked up here: copy the file over and fix what breaks.

## Dependencies without npm

Claude's sandbox can't reach the npm registry. A PR that changes `package.json` gets its `package-lock.json` from the **Lockfile** workflow (`.github/workflows/lockfile.yml`), which commits it to the PR branch; CI runs on the next push.

## Local development

```
npm install
npm run dev:server   # Express on :8000
npm run dev          # Vite dev server, proxying the server routes
```

Without the Authentik variables the app runs open and `/login` answers 501. `npm run build && npm start` runs the production path.

## Tests and lint

`npm test` and `npm run lint`, or `docker build --target test .` / `--target lint .`, which is what CI runs.
